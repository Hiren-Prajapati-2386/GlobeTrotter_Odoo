GlobeTrotter
Hackathon Build Blueprint — Architecture, Database, API & Step-by-Step Implementation Plan
Stack: FastAPI • PostgreSQL • SQLAlchemy • React • Tailwind CSS
1. Overview & Tech Stack
GlobeTrotter is a personalized, multi-city travel planning platform. Users build trips out of ordered “stops” (cities + date ranges), attach activities to each stop, get an automatic budget breakdown, view the trip on a calendar/timeline, and share a read-only public version of the itinerary. An optional admin dashboard tracks platform-wide trends. This document is your build blueprint: architecture, database schema, API surface, and a step-by-step, file-by-file implementation plan with suggested commit messages, mirroring the structure used for the car dealership kata.

3. Database Design (PostgreSQL)
8 tables. Core relational spine: users → trips → stops → trip_activities ← activities, with cities backing both stops and activities.

trips 1──N expenses (miscellaneous costs not tied to a specific activity)

Password hashing + JWT encode/decode.
from datetime import datetime, timedeltafrom jose import jwtfrom passlib.context import CryptContextfrom app.core.config import settings pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto") def hash_password(pw: str) -> str:    return pwd_context.hash(pw) def verify_password(pw: str, hashed: str) -> bool:    return pwd_context.verify(pw, hashed) def create_access_token(subject: str) -> str:    expire = datetime.utcnow() + timedelta(minutes=settings.access_token_expire_minutes)    return jwt.encode({"sub": subject, "exp": expire}, settings.secret_key, algorithm=settings.algorithm)

▶ backend/app/core/dependencies.py
get_current_user reads the JWT, loads the user; get_current_admin extends it.
from fastapi import Depends, HTTPException, statusfrom fastapi.security import OAuth2PasswordBearerfrom jose import jwt, JWTErrorfrom sqlalchemy.orm import Sessionfrom app.database import get_dbfrom app.core.config import settingsfrom app.models.user import User oauth2_scheme = OAuth2PasswordBearer(tokenUrl="api/auth/login") def get_current_user(token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)) -> User:    try:        payload = jwt.decode(token, settings.secret_key, algorithms=[settings.algorithm])        user = db.query(User).filter(User.id == int(payload["sub"])).first()    except (JWTError, KeyError, ValueError):        user = None    if not user:        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Invalid or expired token")    return user def get_current_admin(user: User = Depends(get_current_user)) -> User:    if not user.is_admin:        raise HTTPException(status.HTTP_403_FORBIDDEN, "Admin only")    return user

Signup + login routes.
from fastapi import APIRouter, Depends, HTTPExceptionfrom sqlalchemy.orm import Sessionfrom app.database import get_dbfrom app.models.user import Userfrom app.schemas.user import UserCreate, Tokenfrom app.core.security import hash_password, verify_password, create_access_token router = APIRouter(prefix="/api/auth", tags=["auth"]) @router.post("/signup", response_model=Token)def signup(payload: UserCreate, db: Session = Depends(get_db)):    if db.query(User).filter(User.email == payload.email).first():        raise HTTPException(400, "Email already registered")    user = User(name=payload.name, email=payload.email,                password_hash=hash_password(payload.password))    db.add(user); db.commit(); db.refresh(user)    return Token(access_token=create_access_token(str(user.id))) @router.post("/login", response_model=Token)def login(email: str, password: str, db: Session = Depends(get_db)):    user = db.query(User).filter(User.email == email).first()    if not user or not verify_password(password, user.password_hash):        raise HTTPException(401, "Invalid credentials")    return Token(access_token=create_access_token(str(user.id)))

7. Git Commit Convention
Conventional Commits: type(scope): short imperative summary. Keeps the history skimmable for judges and mirrors the goCar TDD history.

When to use

Commit at the granularity shown in Section 5 — one commit per file or tightly-related file group, not one giant commit at the end. That history is itself evidence of how the app was actually built.
